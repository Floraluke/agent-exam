# 09: 取消流程

**What to build:** 协作者可撤回自己提交的 Job，所有者可取消任意 Job；页面明确区分已请求取消和已取消，执行中只停止后续 Trial，当前 Trial 按冻结超时安全结束。

**Blocked by:** 07 多题进度与部分失败

**Status:** ready-for-agent

**Spec stories:** 30, 31, 32, 51

- [x] 页面和 HTTP 支持既有状态契约允许的取消；协作者仅能取消自己的 Job，所有者可取消任意 Job，调用身份不可由正文伪造。
- [x] 待批准和排队 Job 的取消持久化后不可再被批准或领取；取消与批准/领取的竞争只产生一个一致状态，不出现已取消后仍新启动的 Trial。
- [x] 执行中取消仅设置可信请求并阻止后续 Trial，不强杀当前 Trial；当前 Trial 至多按冻结超时结束并保留实际结果。
- [x] 页面区分请求已受理与真正完成收束，HTTP 返回实际状态；记录请求人、时间、说明和状态事件，不提前宣称执行已停止。
- [x] 重复取消、终态请求和并发状态更新符合既有幂等/冲突契约；已完成证据与结果不可因取消被覆盖或删除。
- [x] 在既有执行生命周期边界接入停止后续 Trial 的能力；若需新的 Interface 变更，先核对并确认，不另建执行后端。
- [x] HTTP 与受控执行替身覆盖每个可取消阶段和竞争窗口；浏览器覆盖请求到终态，PostgreSQL 集成验证取消/领取竞争与事件一致性。
- [x] 独立行动记录记录实际测试、限制和契约同步；无授权不运行真实模型或强杀真实容器，验证后本地提交、不推送。
