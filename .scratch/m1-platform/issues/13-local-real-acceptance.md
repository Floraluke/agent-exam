# 13: 本机真实平台验收

**What to build:** 在用户单独批准的真实运行范围内，通过新平台完成提交、所有者批准、排队、真实 Codex 执行、固定 Fork 判卷、持久化报告与安全证据查询，形成可追溯的本机验收结论。

**Blocked by:** 09 取消流程；10 中断恢复与新建重试；11 基础排行榜；12 制品限额与到期清理

**Status:** ready-for-agent

**Spec stories:** 47, 51, 52

- [ ] 运行前逐项核对 Harbor/认证专题剩余安全、网络与生命周期门槛，区分历史通过、当前缺证、明确阶段例外和真实阻塞；不因 M1 开发而自动豁免。
- [ ] 对真实模型、凭据、容器/网络验证的目的、固定输入、额度、风险、退出及精确清理方案取得本次单独授权；未获授权时仅可做安全只读准备。
- [ ] 新平台真实入口完成提交→等待批准→唯一所有者批准→Worker 领取→真实执行→独立判卷→PostgreSQL/MinIO 持久化→页面报告；创建/批准请求自身仍不执行模型。
- [ ] 核对固定任务、完整配置、一个平台 Job/一个 Harbor Job、逐题身份和 patch 哈希；实际判卷结论和模型/基础设施失败如实保存，不以成功愿望替代证据。
- [ ] 检查正式结果与内部测试数据隔离、排行来源、安全证据及兼容空值；未满足发布保护的原始内容不能经页面/下载流出。
- [ ] 在已授权范围验证适用的生命周期、权限、资源与精确清理门槛；取消与恢复交叉行为、存储故障等本地软件回归完整，未获真实验证的项明确保留。
- [ ] 旧 M0 第四场只作为历史基线，不能计为新平台已通过；失败不自动重跑，需要新范围或额度时重新取得授权。
- [ ] 独立行动记录保留冻结输入、实际结果、证据指针、验证限制和问题状态；敏感原始材料不入 Git，提交仅含可公开代码/文档且不推送。
- [ ] 明确本机验收的通过/未通过项；只有适用门槛全部满足才可宣称本任务完成，私有双机验收尚由任务 14 承担，不提前宣布 M1/MVP 完成。
