# 07: 多题进度与部分失败

**What to build:** 用户提交多任务与配置组合后，可在批次页面看到逐题阶段、已完成结果和部分错误；平台顺序完成每个组合的一次尝试，不因后续失败抹掉先前结果。

**Blocked by:** 06 单题执行与最小报告

**Status:** ready-for-agent

**Spec stories:** 22, 24, 25, 28, 29, 35, 36, 47, 51

- [ ] 实施前核对固定 Harbor 的逐 Trial 进度和生命周期能力；现有同步返回整批结果的 Interface 若需最小变更，说明理由并取得确认。
- [ ] 一个平台 Job 仍只对应一个 Harbor Job，Trial 并发固定为 1；每个任务与配置组合恰好一次尝试，不漏跑、不重复，不把批次拆成多个 Harbor Job 绕开契约。
- [ ] HTTP 和批次页面区分等待批准、排队、准备、执行、判卷、收尾及终态；展示安全阶段说明和逐题身份，不将进程日志文本当作权威状态。
- [ ] 逐题进度和状态事件持久化，刷新或重启读取时不丢已保存状态；重复、过期或错误 Worker 的更新不能倒退或污染结果。
- [ ] 后续 Trial 或判卷失败保留先前可信结果，矩阵准确表达成功、题目未解决、基础设施错误和未完成；批次按既有状态契约表达部分错误。
- [ ] 页面可从矩阵进入每项最小报告；终态不会在证据尚未完成关联时提前宣布全部成功，数据库/对象存储失败可定位。
- [ ] 可控多 Trial 替身覆盖中间失败、乱序/重复进度、超时和部分结果；HTTP 验证可观察状态，浏览器验证刷新与逐题导航，持久化集成验证事件一致性。
- [ ] 所有替身数据保持内部测试隔离；独立行动记录和权威文档同步新增契约与测试证据，关键节点本地提交，不自行进行真实运行或推送。
