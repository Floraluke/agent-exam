# 05: 所有者批准或拒绝

**What to build:** 所有者从 Job 详情核对冻结摘要并批准或拒绝，提交者看到真实决定和状态；批准只给予排队资格，拒绝则终止未开始的运行。

**Blocked by:** 04 提交并冻结评测 Job

**Status:** ready-for-agent

**Spec stories:** 18, 19, 20, 21, 51

- [ ] 所有者页面展示足以判断运行范围的冻结摘要，并通过 HTTP 批准或拒绝；提交者刷新可见决定结果。
- [ ] 只有可信 owner 会话可决定；协作者即使提交自己的 Job 也不能批准，正文不能指定决定者身份或覆盖冻结内容。
- [ ] 只允许待批准 Job 转移；批准成为 QUEUED，不在 HTTP 请求内读取凭据、启动 Harbor 或执行判卷。
- [ ] 拒绝使 Job 终止且未开始的 Run 取消；队列查询不包含待批准和已拒绝 Job，随后 Worker 接线继续验证实际不可领取。
- [ ] 决定者、时间、说明和状态事件原子保存；重复/并发批准与拒绝只形成一个一致决定，冲突符合现有版本和 HTTP 契约。
- [ ] 不可用数据库或事务失败不产生假成功；页面显示拒绝、权限和并发冲突，不将旧状态当作已批准。
- [ ] HTTP 覆盖所有者决定、越权和不执行不变量；浏览器覆盖批准/拒绝，PostgreSQL 集成覆盖并发决定、队列资格和回滚。
- [ ] 新建独立行动记录并同步状态/接口文档，验证后作限定范围本地提交；本任务不开展真实模型或容器实验，不推送。
