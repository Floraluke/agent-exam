# 12: 制品限额与到期清理

**What to build:** 平台对原始制品执行已确认限额，用户看到真实截断或拒绝状态；所有者可从本机受控维护入口清理到期大型原始制品，核心结果和删除审计持续可查。

**Blocked by:** 08 安全证据与轨迹查看

**Status:** completed

**Spec stories:** 37, 38, 40, 42, 43, 44, 51

- [x] 原始制品执行单文件 50 MiB、单运行合计 200 MiB 限额；恰好边界与越界均验证，超限处理可观察，不静默损失正文或无限占用空间。
- [x] 截断标记、实际保留大小和内容哈希保持一致；补丁继续遵守独立阈值且不能截断后判卷，原始制品策略不覆盖补丁契约。
- [x] 只允许所有者本机受控维护清理 30 天后可清理的大型原始制品；不新增定时删除服务或普通 HTTP 删除入口。
- [x] 清理前按受控对象身份确定精确目标；保留核心结果、配置快照、最终 patch 和测试摘要，不以目录级或全局清理替代对象范围。
- [x] 清理保留哈希、大小、创建/删除时间和可信清理审计；重复维护幂等，数据库/对象存储单侧失败可恢复且不留下假删除/假保留状态。
- [x] 页面与 HTTP 区分已删除、未就绪、缺失和完整正文；已删除内容不返回假空文件，仍可查询允许公开的元数据。
- [x] 用合成对象验证单文件/总额边界、截断、到期与长期保留；真实 MinIO/PostgreSQL 集成验证删除审计、重复清理和失败恢复，浏览器验证删除状态。
- [x] 使用独立行动记录同步保留契约和实际测试；不清理现有真实证据或用户服务数据，真实清理需明确目标与授权，关键节点本地提交、不推送。
