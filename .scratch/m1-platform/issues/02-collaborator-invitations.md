# 02: 邀请协作者与成员管理

**What to build:** 所有者通过页面邀请和管理协作者；受邀者建立自己的账号、登录访问获准内容，停用后失去访问能力。平台不开放公共注册或邮件服务。

**Blocked by:** 01 所有者登录与本机恢复

**Status:** ready-for-agent

**Spec stories:** 2, 3, 4, 5, 51

- [ ] 所有者可从成员页面发起受控邀请并查看状态，受邀者可完成加入和登录；邀请凭据不进入普通列表、日志或可共享证据。
- [ ] 邀请的有效期、撤销及一次性使用语义在实施前明确；并发兑换不能产生多份成员身份，失败可解释且可回滚。
- [ ] 普通访客不能自行注册；邀请只能产生 collaborator，不能创建或转移唯一 owner。
- [ ] 所有者可查看和停用成员，停用后的既有会话不能继续获得权限；保留成员历史身份关联，不以删除历史代替停用。
- [ ] 协作者不能邀请或管理成员、伪造角色或获取所有者权限；客户端隐藏按钮不代替后端授权。
- [ ] 账号、邀请与成员状态持久化；新增存储或接口先核对既有职责并按项目规则确认，不预建本任务用不到的权限系统。
- [ ] HTTP 覆盖授权/越权、无效和重复邀请、停用与旧会话拒绝；浏览器覆盖邀请到登录及成员管理，PostgreSQL 集成覆盖并发兑换和回滚。
- [ ] 使用独立行动记录更新实际验收证据与对应文档；不使用真实邮件、模型或用户凭据，按已授权范围本地提交，不推送。
