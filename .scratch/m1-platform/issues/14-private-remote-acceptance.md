# 14: 私有双机协作验收

**What to build:** 在单独批准的私有接入配置与设备范围内，协作者从另一台设备登录、提交并查看结果，所有者在评测机批准；用正反例证明只暴露获准入口且不破坏既有 VPN 出站环境。

**Blocked by:** 13 本机真实平台验收

**Status:** in-progress

**Spec stories:** 48, 49, 50, 51, 52

- [ ] 执行前确认评测机、获准/未获准设备、Tailscale Serve 范围、策略变更与回退方案并取得对应授权；不由任务标签自动安装、发布或更改机器网络。
- [ ] 获准设备经私有 HTTPS Web 同源入口使用应用；后端原始端口、PostgreSQL、MinIO 和 Docker 不对协作者直接开放，不公开互联网入口。
- [ ] 网络成员身份不替代应用账号；真实协作者会话可以提交/查看获准内容，不能自行批准、管理成员/配置或读取无权访问的资源。
- [ ] 双机验证提交→所有者决定→状态刷新→结果/安全证据的接通；如需再运行真实模型，须单独说明并获批，不自动复用任务 13 的一次性运行授权。
- [ ] 既有 VPN 开启与关闭两种状态分别验证获准设备可用、未获准设备拒绝和无额外原始端口暴露；记录实际观察，不把配置存在等同于实测通过。
- [ ] 评测机离线时明确入口不可用；恢复在线后历史 Job、结果与证据状态可查，不为可用性新增云端控制面或自动续跑。
- [ ] 远程页面、下载和错误均符合输出保护，私有原始输出例外不扩展为共享许可；不泄漏真实凭据或完整私有日志。
- [ ] 独立行动记录保存设备/权限正反例、实际网络条件、未验证项及必要回退；同步运维与交接，敏感材料不入 Git，仅作已授权的本地提交。
- [ ] 汇总全部适用 M1 验收证据：未验证、失败或延期均如实标记；只有本机真实闭环、相关安全门槛及双机协作均满足后才能宣布 M1 完成，Judge/Review 继续延期。
