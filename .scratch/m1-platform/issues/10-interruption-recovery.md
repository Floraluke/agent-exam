# 10: 中断恢复与新建重试

**What to build:** Worker、宿主或 Harbor 中断后，所有者可检查历史状态并受控收束；证据充分时幂等恢复结果，否则明确记录基础设施中断。需要重试时创建关联的新 Job，不复写旧尝试。

**Blocked by:** 07 多题进度与部分失败

**Status:** ready-for-agent

**Spec stories:** 33, 34, 35, 51

- [x] 中断或租约失效后旧 Job 不自动续跑、重新排队或调用模型；进程重启不能把未完成记录默认为可重新执行。
- [x] 受控恢复读取已有身份和证据，证据充分才幂等收束；不足、错配或损坏时标明基础设施中断/待处理原因，不伪造确定性结果。
- [x] 重复恢复不重复判卷、执行或写入矛盾事件；过期 Worker 不能继续推进已收束状态，核心结果与既有证据保持不变。
- [x] 用户从页面和 HTTP 看见中断阶段、已保留结果与安全原因；刷新和重启后历史仍可查询，不把无心跳直接解释为题目失败。
- [x] 手动重试以新 Job 关联旧尝试，重新冻结有效配置并重新经过所有者批准；不能直接重启旧 Run 或复用过期执行许可。
- [x] 所需恢复入口及执行生命周期 Interface 的最小方案实施前核对并按规则确认；真实容器强杀、宿主中断和凭据实验不由本任务默认授权。
- [x] HTTP、受控故障替身和真实 PostgreSQL 集成覆盖租约竞争、旧 Worker 更新、证据充分/不足与重复恢复；浏览器覆盖中断详情到新建重试。
- [x] 独立行动记录区分模拟故障证据和仍缺的真实生命周期验收，同步问题状态与契约；关键节点本地提交，不推送。
