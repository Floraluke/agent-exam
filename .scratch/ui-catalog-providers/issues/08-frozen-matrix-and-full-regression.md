## 范围

1. 固定六题 × 两个新 API 配置 = 12 个 Run，与 06/07 两个烟测共计划 14 次真实 Run；每次
   一次尝试、零自动重试、并发 1；两提供方使用同一题集与共同资源/工具限制，差异与不支持
   项显式记录。
2. 全流程从用户页面提交、owner 批准到报告；逐 Run 记录终态、基础设施/题目结果、实际可
   获得用量、账号账额观察与清理结论；失败保留，不复跑筛选好结果。
3. 报告侧交付同题跨配置矩阵与单次详情：五档（已解决/未解决/基础设施错误/未完成/缺失）
   与缺失语义不变；未完成与取消态批次报告保持可读；缺失不计入 `decided`。
4. 执行验证清单：默认后端、Web 类型/构建与浏览器动线、隔离真实存储、代理与固定 Fork
   回归；旧 ChatGPT 用合成链回归，不申请也不消耗真实 `auth.json`；新旧快照均覆盖。
5. 双轴评审、修复、定向重验与必要的全量重验；对产品功能、真实提供方接入、M1-14、长期
   部署分别下结论并逐项列通过/失败/跳过/延期。

## 非目标

- 不改状态机、响应形状与数据库结构；发现缺陷时以最小修复 + 行动记录处理，不借本任务重构。
- 不用跳过基础设施失败的方式宣称全通过；不把缺失写成 0，也不把未完成并入未解决。
- 不扩到 M1-14 的负向/VPN/离线范围（那由 A 主责，需用户另行安排）。
- 不新增业务 Module、公共 Interface 或数据库表。

## 验收

- [ ] 12 个矩阵 Run 每项都有证据和明确结论；14 次真实 Run 全部一次尝试、零自动重试、并发 1。
- [ ] 逐 Run 记录齐备：终态、确定性结果、可获得用量与费用（缺失保持 `null`）、基础设施失败码、证据引用、清理确认。
- [ ] 对比报告可复查：矩阵每格可钻取到单次报告与证据；未知与非零区分；统计分母与未完成分开。
- [ ] 全量回归完成：后端默认门禁、Web 类型/构建/浏览器、隔离真实存储、代理与固定 Fork；跳过项逐条如实列出。
- [ ] 双轴评审（Standards / Spec）通过或明确记录残留；权威文档与代码、数据、接口保持一致。
- [ ] 产品功能、真实提供方接入、M1-14、长期部署四条线分别给出结论；M1-14 未完成时不宣布整个 MVP 完成。

## 停止条件

- 出现超额风险、未知 usage、秘密泄漏或计量状态丢失时，按代理合同关闭当前 Run，不自动补满、
  不切换模型、不重试；先重算预算与授权再批准剩余矩阵。
- 真实失败保留在案，不为"凑满 12 个结果"重跑；矩阵 Run 不必全解对题。
