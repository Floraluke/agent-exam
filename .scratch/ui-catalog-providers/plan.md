## 1. 怎么使用这份计划

1. 先读[需求规格](spec.md)、[实现地图](implementation-map.md)、[验证规则](verification.md)，再读当项依赖的权威文档及源码；不得只看目录树。
2. 只选用户当前安排的一项。开始前记录本地 HEAD、脏文件、评审固定基准、输入身份和执行范围；保留旧增量，更新该项行动。规划修改沿用[本规划行动](../../docs/actions/2026-09-17-ui-catalog-provider-planning.md)，独立实施任务另建行动。
3. 每项按“一个失败用例→最小实现→通过→回归”推进，不先把全部层改完再补测试。技术事实自行核验，新增业务/架构/外部选择再交用户决定。
4. 每项验收后同步权威文档、任务单、行动和 HANDOFF；实施项按 code-review 分别做 Standards/Spec、修复并复验。评审包含现场混合文档，不能只看提交。
5. 每项停下汇报，允许长期暂停。用户说“继续”时只恢复当项/明确指定阶段，不自动消费后续调用或自动启动下一项。提交仅在有对应授权时做精确文件检查点，push 另行确认。

### P：长期持久化与部署准备（历史计划；当前已完成）

**前置：** 用户已确认在 01 后前移本阶段；具体执行仍按用户安排。准备度事实源见[所有者单机架构第 10 节](../../docs/architecture/modules/owner-host-runtime/ARCHITECTURE.md#10-当前代码准备度2026-09-18-实际核对)，详细清单见[独立规格](../persistence-deferred/spec.md)。

**最新停点：** 用户要求将持久化具体化后自行设为执行目标。[行动指南](../../docs/architecture/modules/owner-host-runtime/ACTION_GUIDE.md)维护可发布文本、P1–P5 交付和验收要求；此前只写指南及读源码，Worker 循环未实现。本轮不替用户创建目标、不修改产品代码，也不因准备目标而启动其他阶段；后续若用户明确指定先执行 P，以该次安排为准。

**课设范围：** 遵循[已确认运行约束](../../docs/architecture/modules/owner-host-runtime/ARCHITECTURE.md#11-已确认的课设运行约束2026-09-17)，数据根目录和人工恢复目标已确定；云存储可选，不新增云服务器或生产级高可用系统，云可选不取消备份恢复要求。

**步骤：** 盘点需要保留的数据并固定长期版本/容量/数据目录；补齐持久卷与显式存储初始化，冻结 schema 基线及后续升级/回退流程；按已确认方式实现 Web/API/Worker 手动一键启停及运行期间后台处理，复用一次 claim 入口；建立简单 PG+MinIO 一致备份及隔离恢复，核查引用/摘要；验证跨重建/重启的数据保留、Job 中断收束和存储端口隔离。后续 04–07 改变 SQL 约束时必须交付针对该基线的升级路径。

**验收：** 在获授权的专属长期环境保存合成数据，重建/重启后可读回；恢复到新的隔离位置后账号、Job/Run、制品引用及摘要吻合；不向协作者开放存储/容器端口；中断不自动重跑或消费模型。一键启停、不随开机自动启动和停止后的数据保留须验证；本机导出不能冒充异机防灾副本。

**停止：** 数据集合或目标路径不明确、备份不可恢复、升级/回退不能保留旧数据或隔离不足时，不进入正式组内使用或 06/07 真实 API。完整远程组内使用还需要原 M1 任务 14 验收；不把它误列为本机单题 API 的额外技术前置。02–05 的隔离开发/假值验证技术上可独立准备，不能借此上线正式使用。

## 3. 01：先把界面做成可点的 HTML

**前置：** 用户安排开始原型；仅读取现有页面与 API，所有数据为明显标记的假数据。

**步骤：**

1. 给出三种结构不同、同为浅色的低保真布局：侧栏工作台、紧凑任务收件箱、分区概览。用 `?variant=` 与可见切换器比较，不把换颜色当不同方案。
2. 每种至少覆盖 owner/协作者首页、新建向导和结果入口；选定结构后把审批、详情、报告、目录、成员、恢复与清理入口补齐。原型使用本地 HTML/CSS/JS，不引入构建依赖，不连接真实服务。
3. 用场景切换展示空列表、待批准、排队、执行、完成/未通过、基础设施故障、取消、无权限、过期会话、断网、过期制品、缺失轨迹/用量。执行状态以 Job/Run 事实命名，不制造 Worker 在线信息。
4. 手机设计以 390px 为主，并覆盖 360px；桌面以 1440px 为主并覆盖 1280px。手机的矩阵允许在带标题的区域横向滚动，主导航和审批/提交按钮不能被截断。
5. 与用户逐轮看图和点击；记录选择、改动、尚未确认点。最终冻结一份页面清单、交互说明和桌面/手机截图，用于 02/03 验收。

**验收：** 两角色完整模拟流程可点；按钮无误导；键盘焦点/表单错误清楚；无真实网络写入、无秘密；用户明确确认选定版本。原型完成不等于 UI 已落地。

**完成记录：** 用户于 2026-09-18 明确选择纯 A「侧栏工作台」，不组合 B/C；任务 01 到此完成。若某展示缺现有数据，只标未知/暂不展示；新增业务接口另请确认。

## 4. 02：角色首页到提交/审批的真实闭环

**前置：** 01 原型确认；现有 HTTP、会话、Job/Run 和浏览器测试必读；本项先不改批次规模。

**步骤：**

1. 先按 A 版页面清单逐项建立交互契约表：控件/状态、前端处理、HTTP 方法/路径/请求、响应解析、后端路由与用例、权限、稳定错误、成功后重新读取及测试。纯前端动作明确写“无后端请求”；找不到现有契约时标为接口缺口并停止，不臆造 API。
2. 在现有 Web 会话壳内拆出工作台与导航，默认随 actor 角色选择首页；使用现有查询参数/Job 链接，保留收藏链接与浏览器前进后退。登出清掉私有页面状态。
3. 复用列表 HTTP 的筛选和游标，提供“我的/可见评测”、状态、上一页/下一页；不凭第一页条目推断全局计数，不把 UUID 顺序当最近创建时间。
4. 三步向导从服务端读取可选题/配置/规模；切换步骤保留选择、提交中锁按钮。相同未决请求保留幂等键，明确改变题/配置后新建请求；超时按原键重试，不制造重复 Job。
5. 提交成功进入详情，明确等待批准；owner 自己提交的也保持该流程。审批查看冻结摘要，成功后重新读服务端状态；协作者 UI 隐藏管理操作，服务器仍做最终拒绝。
6. 在同一导航内接回既有取消、恢复/重试入口，保留各自业务条件、确认和关联 Job；不为 UI 改成自动批准或自动续跑。

**验收：** A 版每个可操作控件在契约表中有且只有一个归属，并有对应测试或明确的纯前端断言；HTTP 身份/越权/幂等行为不变；owner 自提交自批与协作者→owner 两条浏览器流程通过；手机完成提交/审批/取消/新 Job 重试；空、错误、重复点击、刷新、分页有测例；无新表/公共接口。

**停止：** 源码与 API 不符先修正文档/最小缺口；若需要新增 Worker 健康、总数统计或新业务能力，先留空，不扩张本项。

## 5. 03：先看对比，再看单次证据

**前置：** 02 的会话/导航壳；选定报告原型；既有批次、Run 报告、制品/轨迹、排行榜、保留清理合同。

**步骤：**

1. 复用批次报告建“题×配置”矩阵，汇总确定性通过数、未通过、基础设施故障、未完成；缺失 Run 或报告标为缺失，不当作未通过或零。
2. 通过已有 Run 报告取得资源/用量；惰性加载或限制并发，避免一屏发 60 个无界请求。只在所有组成值可用时称“总量”；否则标为部分/未知。说明耗时是 Run 用时汇总而非整批墙钟耗时。
3. 展示冻结型号、版本、限制、工具/网络策略差异；排行榜继续使用既有可比性分组，不以 UI 计算替代既有排序或引入 Judge 分。
4. 单元格进入单次详情，保留确定性判卷、安全日志/补丁/轨迹、下载和过期提示。错误码附通俗说明，技术字段折叠；费用继续按可靠原币/现有美元合同，人民币预算不是实际账单。
5. 题库、配置、owner 成员/保留管理置于独立导航，协作者仍可看其获准的非秘密目录。整合现有能力，不增加 Key 页面。

**验收：** 混合成功/未通过/故障/取消/缺失报告的矩阵和汇总正确；页面权限不变；桌面/手机均能钻取详情、下载与处理管理操作；零用量与未知明确不同；既有全部 UI 动线无功能丢失。

**停止：** 某指标没有来源就显示未知；不为漂亮报表估造价格、准确率或补写模型轨迹。用户确认 UI 后再安排题库阶段。

## 6. 04：五道新题合格入库，打通六题提交

**前置：** 用户安排题库阶段；固定数据、Fork、镜像和专属存储条件可核验。技术上不依赖新 UI，但按用户节奏在 UI 完成后进行。

**步骤：**

1. 逐个读取固定快照记录，冻结 instance、base commit、公开题干摘要、隐藏判卷字段摘要及镜像 digest。先列本地缓存/缺失镜像、磁盘需求和下载来源；没有下载范围授权时不拉镜像。
2. 按候选顺序资格验证：`python__mypy-15184`、`python__mypy-15208`、`python__mypy-15131`、`python__mypy-15139`、`python__mypy-15876`。它们只是同项目候选，不能共用旧题镜像。15876 额外检查是否有真实 FAIL_TO_PASS，不能用仅文档修改凑数量。
3. 每题独立容器、固定 Fork、外网关闭，先参考补丁、再空补丁、再可应用但错误的补丁；确认测试实际执行且参考通过、负例未解决。基础设施错误不算负例成功，空补丁本来通过的题不合格。记录镜像/数据/报告身份与精确清理。
4. 只有通过门禁的题才进入受控目录白名单；保留旧题身份与 M0 单题入口。某候选不合格时从同一固定 mypy 集合选替补、重走全部门禁；不足五题则停止汇报，不无声改项目/数据集。
5. 引入新的连续规模预设；保留旧 ID 对历史冻结值的解释。新增 4/6/9 题请求必须通过，0/21 题、0/4 配置、重复 ID、未知/停用项拒绝；上限 20×3=60，用合成受控目录验证，不要求现在准备 20 道真实题。
6. 打通目录→HTTP选项→三步向导→冻结 Job/全部 Runs/初始事件的事务；创建只返回等待批准。验证读旧 Job、恢复新 Job、双存储一致性与指纹/摘要防漂移；同步权威文档。

**验收：** 原题+至少五道新题合格可选；五组参考/空/错误判卷证据齐备；六题×三配置的合成提交、20×3边界和旧快照兼容通过；不读真实 auth、不调用模型、隐藏答案不出做题侧或 HTTP。

**停止：** 任一记录/镜像/测试不匹配就隔离该候选；磁盘/下载/时间超出本阶段已定范围时暂停。至少五道未完成就不能把任务标完成。

## 7. 05：让假提供方先走完安全执行链

**前置：** 用户安排 API 阶段；先确认候选内部树与安全实现合同。无真实 Key，无公网请求。已有 5/5 假配置探针只作历史输入，不重复计为本项通过。

**步骤：**

1. 冻结代理拓扑、Key 文件格式/权限验证、可允许请求字段与计量策略。按[认证合同](../../docs/interfaces/CODEX_AUTHENTICATION.md#41-codex-第三方-api-扩展规划2026-09-17)先做最小拓扑实证：做题容器仅能到专属代理；真实上游网络仅在代理侧；PID/文件系统隔离、无主机发布端口/容器套接字。
2. 以 `internal_test` 的受控 API 配置走正式 Registry→提交→批准→Worker→Harbor；假 Key 只进代理私有内存，做题侧固定 config.toml 只含代理地址、模型与短命令牌来源。生产目录不能登记假服务。
3. 代理固定上游/模型、Run 身份、过期时间、路径/请求大小/请求速率/预算；剥离客户端鉴权再由可信侧添加 Key。拒绝任意 URL、重定向、其他模型、远程工具、跨 Run 令牌、过期重放和未知字段；逐条测试拒绝在出站前发生。
4. 假服务返回 Responses 流与本地工具调用，完成一次工具循环、补丁收集、固定判卷/报告；再注入 401/429/5xx、断流、超时、未知 usage、超限等，不自动重试/切模型。并发时预留额度须原子，流中断不得退款为零。
5. 接入现有终态、协作取消、强制超时和崩溃恢复：回收代理/令牌与任务专属资源；崩溃后只能按已有持久化证据收束，不自动续跑。计量状态遗失时拒绝再用旧额度，不重置为满额。
6. 真/假秘密均不得进入 argv、共享 env、inspect 可见配置、日志、数据库、制品或 UI；做题侧能被攻击者拿到的 Run 令牌仍受限并会过期，不能宣称完全不可窃取。
7. 运行隔离 PG/MinIO、假网络/浏览器及旧 ChatGPT 合成回归。安全门槛通过后记录网络图、威胁/限制、配置摘要、失败和清理，才允许请求真实 API 阶段。

**验收：** 正式链路的合成 Run 可完成；未批准零出站；假长期 Key 在做题侧/公开输出零命中；跨 Run/超额/超时/未知使用量/故障关闭全部可证；ChatGPT旧链未退化；无新增表或第二执行接口。

**停止：** 拓扑无法落实、固定 CLI 无法闭卷执行、预算缺失时仍可出站，任何一项都阻断真实 Key。不能降级为真 Key 进做题容器、放宽到公网、静默换 CLI 或实现协议桥。

## 8. 06：DeepSeek 单题先行

**前置：** P 与 05 全部门禁；确认 `deepseek-flash` 当前仍对应用户型号、官方原生接口、实际账号地区与可用额度；固定配置/价格快照；真实阶段单独授权。

**步骤：** 先用假服务对已冻结 DeepSeek 预设跑目录/快照/配置渲染/报告回归；无 ChatGPT auth 的机器配置也应能准备该提供方。再由 owner 私有文件绑定 Key，经现有提交/批准链执行旧固定题一次，零重试；核验真实 Responses、工具命令、补丁、Fork、报告、用量/未知、令牌回收和本次账额。模型未解题与基础设施失败分开。

**验收：** 原生接口真实工具循环可用，完整 Job/Run 终态与独立判卷可查；不要求模型必须解对旧题，但仅有 HTTP 200/自然语言回复不算接入通过；观察到的模型身份、关键配置摘要及账户计费证据已记录。

**停止：** 模型漂移、权限/余额/限流、工具协议不兼容或安全泄漏，立即停本提供方；不自动充值、重试或替换模型。真实失败同样占验收次数/预算。

**验收：** 与 06 相同；新增明确断言订阅端点/订阅认证不能作为此预设的成功路径；缺少计费资格就保留未运行，不为验收充值。

**停止：** 地区/账户/协议不匹配、需更换用户选型或安全条件不足时停止并汇报；不自动改国际区、不挪用其他 Key。
