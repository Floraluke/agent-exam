## 3. 结果展示回归：用例映射

编号前缀 `B06-` / `B07-` 表示任务归属；两层分开列，**同一场景在两层各有一条**。

| 编号 | 场景 | 断言 | 依赖 |
|---|---|---|---|
| `B06-01` | 目录里出现 DeepSeek 预设 | 配置目录显示提供方与型号；**不显示**任何 Key、凭据 profile、宿主路径（story 21、Q13） | 预设 id/别名冻结 |
| `B06-02` | 报告首屏 | 先给出各配置的通过题数、耗时、**可获得**用量；再给"每题一行、配置一列"矩阵（story 24） | — |
| `B06-03` | **负例**：某项用量缺失 | 显示"未知"，**不得显示 0**，不得按 0 参与合计（story 25；§10.2） | — |
| `B06-04` | **负例**：一个 Run 是基础设施失败 | 与"未通过"分开呈现；确定性结果为空时保持未知，不冒充未解决（story 25；§10.2） | — |
| `B06-05` | **负例**：某 Run 没有轨迹 | 明确显示缺失，**不伪造补齐**（story 25） | — |
| `B06-06` | **负例**：从对比单元格进入 | 单元格只有同时有 `run_id` 与 `report_path` 才提供入口；`missing` 不伪造按钮（story 26；§10.4） | — |
| `B06-07` | 制品权限与过期 | 访问权限与过期提示不减弱；受限类型只展示元数据（story 26；§9.2） | — |
| `B06-08` | 排行榜可比性 | 换 provider 后**不能**把不同冻结条件混进同一排名；过程指标仍只展示、不参与排序（story 27；§10.3） | — |
| `B06-09` | **负例**：未知提供方值 | 目录/详情对超出受控集合的记录**失败关闭**，不回退成默认值（§4.2） | — |
| `B07-01…09` | 同 `B06-01…09` | 同上断言，数据集换成 Kimi 预设；**额外的强断言**：请求走开放平台原生 Responses，**不出现** Kimi Code 订阅端点（Q9） | 同上 + 07 的端点冻结 |
| `B0X-10` | **负例**：自动重试 | 展示层不引入任何自动重试；失败就是失败（Q11） | — |

**说明**：`B06-03/04/05` 三条是 story 25 的原话要求，也是 B 侧**最容易做成"看起来更好看但失真"**的地方——展示回归的核心就是"未知保持未知"。
