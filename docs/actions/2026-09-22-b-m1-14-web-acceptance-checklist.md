## 1. 正向：协作者从另一台设备走完闭环（浏览器侧）

逐步执行，**每步都记"预期 / 实际 / 证据"**：

1. 在获准设备上经**私有 HTTPS Web 入口**打开应用（不是原始 API 端口）。
2. 用**应用账号**登录——网络成员身份不替代应用账号（任务单第 13 项）。
3. 新建评测：走三步向导提交一个批次。
4. 提交后状态必须是**等待所有者批准**；**协作者自己不能批准**（UI 不出现批准按钮）。
5. 通知 owner 在评测机批准；B 刷新后看到状态推进（`QUEUED` → 执行中 → 终态）。
6. 打开**批次进度**与**单题运行报告**；展开**安全证据**，下载公开三类制品之一。
7. 记下每步的状态码/文案与截图编号；任何一步失败就**停在那里**并记录现象。

## 2. 反向：不该能做的事（每条都要实测，不能只看配置）

| 反例 | 断言 |

| 页面/下载/错误 | 符合输出保护：**不出现内部码、文件路径、令牌片段**——可复用既有的页面哨兵扫描（`apps/web/tests/job-evidence.spec.ts` 的 `SENTINELS`） |

## 3. VPN 两态 × 离线/恢复

- **VPN 开**与**VPN 关**各测一次：获准设备的 HTTPS Web 与 PostgreSQL `55432` 可用性、未获准设备拒绝。
- **评测机离线**：入口必须明确不可用（给出可理解的错误，不是超时假死）。
- **恢复在线后**：历史 Job、结果与证据状态**可查**；**不新增云端控制面、不自动续跑**（任务单第 16 项）。
- 局域网 PostgreSQL 直连的组员侧正负例**属 A/D 的切片**，B 只记录协同观察，不代为勾选。

## 4. 证据与记录纪律

- 每项如实标**实测 / 未验证 / 失败**；**"配置存在"不等于"实测通过"**（任务单第 15 项）。
