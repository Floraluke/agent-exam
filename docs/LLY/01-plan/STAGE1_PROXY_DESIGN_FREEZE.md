## 2. 可直接依据的既有事实（不需重新验证）

1. **固定 CLI 支持文件方式的自定义 Responses 入口**：TOML 指定 `deepseek-flash` / `kimi-k3` 时，假服务实际收到 1 次 `POST /v1/responses`，模型名与假 Bearer 匹配、`stream=true`。`wire_api="chat"` 在该版本不被接受；缺配置指定的令牌环境变量时在模型请求前拒绝。来源：研究第 6.1 节（探针 5/5）。
2. **命令行可覆盖模型**：`-c model="kimi-k3"` 会实际改变请求中的模型名。因此**安全限制必须由代理与网络执行，不能只信任 TOML 文件**。来源：研究第 6.1 节。
3. **默认重试不是零**：Codex 官方配置提供 `request_max_retries`、`stream_max_retries`，默认值并非零，需显式关闭并由代理验证没有发生重发。来源：研究第 1 节。这是此前设计稿里没有的硬约束。
4. **现有侧车不能照搬**：`adapters/execution/network.py` 的侧车（`harbor-docker-egress-control-sidecar`）是 gost + nftables allowlist；其 `compose_profile()` **刻意不声明 `networks`**，由 Harbor 环境附加自己的侧车，因此主容器与侧车共享网络命名空间。这与认证接口第 4.1 节第 5 条的警告一致——照搬后不能宣称防绕过。

## 3. 待冻结项与候选设计

### 3.1 代理拓扑（候选；结论须由组长机器实证）

- **候选结构**：两组网络。内部网络 A 只含"做题侧 + 代理"；代理侧网络 B 具备受控出网。做题侧**不接** B，也不接默认 bridge。
- **与现有侧车的关系**：不复用 Harbor 的隐式侧车附加方式。需要在 Harbor docker 环境层允许替换网络附加，或采用等价的隔离手段。
- **第一个要回答的问题**：固定 Harbor 上游的 docker environment 是否允许替换/绕过它的侧车附加。这决定候选结构能否成立。
- **若不可行**：按计划第 7 节停止条件停在本任务，不带真实 Key，不放宽到公网。

### 3.2 私有文件格式与权限拒绝条件（候选）

- **位置**：已确认使用 Git 工作树之外、由当前 Windows 用户持有的普通私有路径；实际绝对路径不写入 Git，由本机运行参数提供。不放仓库 `.env`，不放共享或同步目录。
- **结构（候选）**：单一 JSON，含结构版本号与"逻辑 profile → 提供方/模型/上游基址/Key"的映射。上游基址只能是登记值，**不接受任意 URL**；不含 Key 明文时改为指向 owner 私有的另一处。
- **权限规则**：仅 owner 与必要系统主体可读。**拒绝**：符号链接、共享/同步目录、组或其他用户可读的宽权限、非普通文件。
- **读取范围**：只读当次已批准 Run 所需的那一个 profile；Web、提交、审批路径均不读。
- **环境变量**最多携带**文件定位**，绝不携带 Key 值。
- 任一条件不满足即失败关闭，错误信息不回显路径或 Key。

### 3.3 请求字段白名单与拒绝规则（候选）

- **允许的请求**：只有 `POST {代理基址}/responses`（相对基址为 `/responses`）。
- **允许的字段（候选）**：`model`（必须等于该 Run 的绑定值）、`stream`、`input`、`tools`（仅做题所需的受控工具）、`max_output_tokens`（不得超过该 Run 剩余输出额度）、以及冻结配置内的 `instructions` / 推理参数。
- **出站前拒绝**：未批准、错误 profile、缺 Key、宽权限或链接形式的私有文件、任意或绝对 URL、重定向（不跟随）、其他模型、路径越界、内置付费能力（联网搜索、文件上传等）、跨 Run 令牌、过期或已撤销令牌、**未知字段**、超限请求。
- **规则强度**：未知字段**一律拒绝**，不是忽略。客户端 `Authorization` 一律剥离，由可信侧添加真实凭据。
- **响应侧**：保留 `usage`，关闭秘密与正文日志。

### 3.4 计量与账本（机制候选）

机制依据研究第 5 节，逐条对应：

1. 接收请求前检查 Run 身份、指定模型、截止时间与剩余额度；按非缓存价**保守预留**"输入上界 + 本次最大输出"；客户端不能修改价格表、模型或限制。
2. 输入计数选择 **A 保守上界**。实现必须定义高估公式与适用字符集，并以正反样例证明不低估；普通字符串长度不是准确 Token 数。该选择只允许承诺保守上界，不允许承诺精确账单或金额硬上限（研究第 5 节第 1 条明示"必须定义并验证"）。
3. `max_output_tokens` 不得超过该 Run 剩余输出额度。
4. 完整 usage 到达后结算；**usage 缺失、流断开或异常时不退回未知部分、不以"客户端没收到"推断没计费，并停止该 Run 的后续请求**。
5. 每 Run 累计用量与整批金额需**共同约束**；某个 Run 的剩余额度**不得因代理重启被重置**；记录不含 Key 或临时令牌；**失去已花费证据时失败关闭，不重新发放全部预算**。
6. 禁用模型内置的付费联网搜索、文件上传与其他额外计费能力。

### 3.5 令牌绑定与生命周期（候选）

- 令牌绑定：单个 `run_id` + 固定 provider/模型 + 截止时间 + 预算上限。**多轮请求共用**，不是一次性码（一个 Run 可包含多轮）。
- `config.toml` 的 `env_key` 引用承载该令牌的环境变量名；令牌值由运行时注入做题侧。
- 撤销时机：Run 正常结束、失败或超时后撤销；**期限作为兜底**。
- 明确不宣称"完全不可窃取"：做题侧能取得的令牌仍有被滥用的可能，只能限制在绑定范围内。

### 3.6 配置渲染（候选）

- 渲染固定 `$CODEX_HOME/config.toml`：自定义 `model_provider`、`base_url` 指向代理入口、`env_key` 指向令牌变量、`wire_api = "responses"`。
- **必须显式写入 `request_max_retries = 0` 与 `stream_max_retries = 0`**（依据第 2 节事实 3），并由代理侧独立验证没有重发——不能只依赖配置文件被遵守（依据事实 2）。
- 渲染结果记录摘要（哈希）供兼容性核对；结果中不得出现 Key、真实上游地址或宿主路径。
