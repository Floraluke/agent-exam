## 2. 三条硬约束（先认清，能省很多返工）

1. **真实执行链只在组长的机器上。** 外部执行框架（Harbor）、固定独立判卷框架（SWE-Bench-Fork）、固定镜像以及 `framework/`、`runtime/` 目录都不进 Git。文档明确要求不要无理由重建 Harbor/Fork 环境（Windows 上首次编译 Harbor 曾耗时约 275 分钟）。所以本机（开发机）能做的是：**写代码、跑单元与契约测试、用替身验证逻辑**；真实跑题必须到组长机器上完成。
2. **真实模型调用需要单独授权。** 05 的全部门禁通过后，06/07 才允许申请一次真实单题试跑；历史上 ChatGPT 的三次许可**不覆盖** DeepSeek / Kimi。
3. **秘密不进入共享位置。** API 密钥（API Key）只由组长在本机私有文件中管理，不进做题容器、HTTP、PostgreSQL、MinIO、命令行、日志或轨迹。

## 3. 阶段计划

顺序固定为 **05 → 06 → 07**，04 与 08 配合。每阶段完成即停并汇报，不自动进入下一阶段。各阶段的完整步骤、逐条验收和停止条件以[扩展执行计划](../../../.scratch/ui-catalog-providers/plan.md)为准，本节只列我这一侧的安排与"在哪台机器做"。

### 阶段 0：本地开发环境（已完成，不涉及产品代码）

- **目标**：在本机建立一套**不依赖 Tailscale、共享管理员和 Docker** 的开发环境，能写代码、跑静态检查、PostgreSQL 集成测试和默认回归。
- **已确认设计**：采用两库隔离；`agentexam_identity_test` 只供自动化测试并拥有 `CREATEDB`，`agentexam_dev` 只供日常开发并安装完整 11 表 schema。PostgreSQL 只监听 `127.0.0.1:55432`，不注册 Windows 服务、不设置开机自启。
- **阶段 0 收尾时点事实（2026-09-19）**：PostgreSQL 15 与数据目录、Python `.venv`、两库隔离、开发 schema、静态检查、PostgreSQL 集成测试和启停读回均已就绪；当时默认回归有 2 个因缺少 `framework/harbor` 的环境失败，详见 ISSUE-04。该数字不是当前 `main` 的固定基线；最新项目级验证看根目录 `HANDOFF.md`，本机环境恢复后仍须现场复核。
- **实施入口**：[阶段 0 设计](./STAGE0_LOCAL_DEVELOPMENT_DESIGN.md) → [阶段 0 详细实施计划](./STAGE0_LOCAL_DEVELOPMENT_PLAN.md) → [本地环境事实记录](../02-environment/LOCAL_SETUP.md)。
- **停止**：详细计划的本机门禁已完成；执行结束时数据库保持运行，实时状态以[本地环境记录](../02-environment/LOCAL_SETUP.md)为准。本阶段不产出产品代码改动，也不自动进入任务 05。

### 阶段 1：05 假提供方安全执行链（24 h，主责）

- **目标**：让**假提供方**走完正式执行链，把安全边界用可证的方式固定下来，为真实 Key 放行做门禁。
- **我这一侧的产出**：provider 代理与请求策略、假 Key 与假上游、假服务工具循环、网络与超时清理、`internal_test` 受控配置的运行时接入。
- **本机可做**：代理逻辑、请求校验、配置渲染、协议与拒绝用例的单元/契约测试；用假服务跑通工具循环。
- **必须到组长机器**：正式 Harbor 链路、容器与网络隔离、真实镜像的精确清理。
- **验证**：正式链路合成 Run 可完成；未批准零出站；假长期 Key 在做题侧与公开输出零命中；跨 Run / 超额 / 超时 / 未知使用量 / 故障关闭全部可证；旧 ChatGPT 链未退化；无新增表、无第二执行接口。
- **停止（阻断真实 Key）**：代理拓扑无法落实、固定 CLI 无法闭卷执行、预算缺失时仍可出站——任一项不通过就停在本阶段。

### 阶段 2：06 DeepSeek 单题（8 h，主责）

- **前置**：P 已完成；05 全部门禁通过；已核验当前官方型号、原生接口、账号地区与可用额度；固定配置与价格快照；真实调用**单独授权**。
- **产出**：DeepSeek 固定预设、假服务回归、一次真实旧题（零重试）的完整证据。
- **验证**：原生接口的真实工具循环可用；完整 Job/Run 终态与独立判卷可查。**不要求模型解对题**，但只有 HTTP 200 或自然语言回复不算接入通过。
- **停止**：模型漂移、权限/余额/限流、工具协议不兼容或安全泄漏，立即停用该提供方；不自动充值、重试或替换模型。

### 阶段 3：07 Kimi 单题（8 h，主责）

- 与 06 同一路径，独立冻结 Kimi 的模型目录、推理参数与请求格式。
- **额外要求**：必须使用开放平台原生 Responses，**不复用** Harbor 内置 Kimi Code 订阅端点；需新增明确断言——订阅端点 / 订阅认证不能作为本预设的成功路径。
- 06 不是技术前置，但按既定节奏在 06 之后做。

### 阶段 4：04 与 08 配合

- **04 配合（已完成）**：五道候选题（`python__mypy-15184/15208/15131/15139/15876`）的固定 Fork 资格验证已按**参考补丁 → 空补丁 → 可应用但错误的补丁**完成，15/15 场景通过并进入六题白名单；不得按本段重复执行。
- **08 配合（4 h）**：冻结六题 × 两配置 = 12 个 Run 的矩阵执行与回归，每次一次尝试、零自动重试、并发 1；逐 Run 记录终态、题目与基础设施结果、可获得用量及清理，失败保留不复跑。

## 4. 协作约定

- **分支**：个人开发在 `lly/dev` 上进行；`main` 保持与 `origin/main` 一致，不直接改。
- **提交**：只提交本次改动明确涉及的文件，避免把无关增量一起提交；推送需单独确认。
- **行动文档**：每次独立行动在 `docs/actions/` 新建一份记录（本次为 2026-09-18 那份），同一行动内持续更新，不新建重复记录。
- **交接**：按[团队分工文档](../../architecture/modules/TEAM_WORK_ALLOCATION.md)第 7 节的八项清单，向上游要输入、向下游交付输出。
- **文档边界**：本目录只做过程记录；项目级事实提升到权威文档，见[本目录说明](../README.md)。

## 5. 风险与未知

| 风险 | 影响 | 当前处理 |
|---|---|---|
| 本机 Tailscale 虚拟网卡装不上 | 无法连团队共享库看数据 | 已决定阶段 0 不使用共享库，改用隔离的本地测试库与开发库；问题保留在[本机环境问题](../04-issues/KNOWN_ISSUES.md)，但不阻塞阶段 0 |
| 真实执行链只在组长机器 | 本机无法端到端验证 | 本机只做单元/契约层；真实验证排到组长的机器 |
| 真实模型用量与价格会变 | 预算估算可能失真 | 真实阶段前重新核验官方资料与账户资格 |
| 代理计量与崩溃残留 | 可能超支或残留资源 | 列为 05 的必测项，未验证不放行真实矩阵 |
