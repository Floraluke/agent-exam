### 0.2 核心代码阅读摘要

当前调用链是“Worker 组合 → 应用编排 → `ExecutionBackend` port → Harbor Adapter → 固定 Harbor Job/Trial → 固定 Codex Agent”。关键事实如下：

- [Worker 组合](../../../apps/backend/src/eval_platform/delivery/worker/runtime.py)只允许 `auth.openai.com`、`chatgpt.com`，并强制读取 `AGENTEXAM_CODEX_AUTH_PATH`；这不是 DeepSeek/Kimi 的代理接入。
- [目录数据库约束](../../../apps/backend/src/eval_platform/adapters/persistence/catalog/schema.sql)、[目录 HTTP schema](../../../apps/backend/src/eval_platform/delivery/http/catalog_schemas.py)和[Agent Registry](../../../apps/backend/src/eval_platform/application/agent_registry.py)当前都只接受 `openai_chatgpt`。
- [Harbor 引导](../../../apps/backend/src/eval_platform/adapters/execution/harbor_entry.py)要求唯一的固定 Codex 配置；虽然[配置映射](../../../apps/backend/src/eval_platform/adapters/execution/harbor/config_mapper.py)能拼接 provider 字符串，正式引导仍会拒绝非固定配置。
- Harbor 配置当前固定 `n_concurrent_trials = 1`、Harbor 层 `retry.max_retries = 0`。这**不能**替代固定 Codex CLI 的 `request_max_retries`、`stream_max_retries` 显式置零，也不能证明代理没有重发。
- [当前网络适配](../../../apps/backend/src/eval_platform/adapters/execution/network.py)刻意不声明业务网络，由 Harbor 附加出站侧车；主容器与侧车共享网络命名空间。它不能证明任务 05 所需的“做题侧只通专属代理，只有代理侧可出网”。
- [认证合同](../../interfaces/CODEX_AUTHENTICATION.md)把第三方代理链标为规划能力；现有认证文件校验只检查普通非链接文件及大小，不足以证明 Windows ACL/属主满足任务 05 的私有文件要求。
- [完整假凭据 Trial 测试](../../../apps/backend/tests/test_codex_trial.py)保留了假秘密可进入原始日志、session、trajectory 或 patch 的当前边界证据；它不是任务 05 的“零泄漏”证明。
